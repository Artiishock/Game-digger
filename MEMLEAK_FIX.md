# Утечка памяти при подборе предметов — диагноз и фикс

> **Симптом:** JS-хип растёт ~1 МБ/с и не освобождается. На iPhone Safari убивает вкладку
> (перезагрузка) за ~8–20 мин игры. Падение происходит посреди раунда, в т.ч. в автоигре.

---

## 1. Где течёт

**Файл:** `src/game/GameRenderer.ts`

Каждый собранный предмет (монета / кристалл / бомба) оставляет за собой «осиротевший»
`PIXI.Graphics`, который навсегда остаётся прицеплен к `objectsLayer` — невидимый,
но не уничтоженный и не отцепленный от сцены.

### Цепочка

| Шаг | Код | Что происходит |
|-----|-----|----------------|
| 1 | `_onCollect` → `_animCollect(obj.gfx, obj.spine)` | `GameRenderer.ts:3987` | запускает анимацию «улёта» предмета |
| 2 | `_animCollect` | `GameRenderer.ts:4282` | снимает Spine (корректно), кладёт `gfx` в `_collectAnims` |
| 3 | culling-фильтр | `GameRenderer.ts:838` | `if (o.collected) return false` — объект выкинут из `this.objects` **без** `_disposeSpawnedVisual` |
| 4 | конец анимации | `GameRenderer.ts:4340` | `gfx.visible=false` + `pop()` из `_collectAnims` — **gfx не уничтожен и не отцеплен** |

После шага 4 на `gfx` больше никто не ссылается из логики, но он остаётся ребёнком
`objectsLayer`. Сборщик мусора его не заберёт (есть ссылка от сцены), деструктор —
тоже (объект уже не в `this.objects`). Так каждый подбор добавляет один мёртвый
display-объект. При копании это несколько штук в секунду.

### Проблемное место (строки 4340–4343)

```js
if(a.t>=1){
  a.gfx.visible=false        // ← только прячет
  this._collectAnims[i]=this._collectAnims[this._collectAnims.length-1]!
  this._collectAnims.pop();continue
}
```

---

## 2. Как чинить

В проекте уже есть хелпер `safePixiDestroyDisplay(...)` (`GameRenderer.ts:353`),
который используется в других путях уборки. Нужно вызвать его здесь.

### Минимальный фикс (строки 4340–4343)

```js
if(a.t>=1){
  safePixiDestroyDisplay(a.gfx)   // отцепляет от родителя + .destroy()
  this._collectAnims[i]=this._collectAnims[this._collectAnims.length-1]!
  this._collectAnims.pop();continue
}
```

> Проверь, что `safePixiDestroyDisplay` делает и `removeChild`, и `.destroy()`.
> Если он только destroy без отцепления — добавь перед ним:
> `if (a.gfx.parent) a.gfx.parent.removeChild(a.gfx)`.

### Заодно — ветка «уже уничтожен» (строки 4333–4335)

Там объект просто выкидывается из массива — это ок, потому что он уже destroyed.
Менять не нужно.

### Опционально (лучше, но больше работы): пул

По аналогии с `_particlePool` / `_floatTextPool` можно не уничтожать `gfx`,
а возвращать в пул и переиспользовать — меньше нагрузка на GC. Для фикса утечки
это не обязательно: достаточно `destroy()`.

## 3. Проверить, что починилось

1. Safari (десктоп) → **Develop → Show Web Inspector → Timelines → JS Allocations**.
2. Запусти раунд, поиграй ~30–60 сек, собирая предметы.
3. До фикса: пила вверх без спада, в снапшоте — куча detached `Graphics`.
4. После фикса: хип стабилизируется, число `Graphics` в снапшоте не растёт линейно.

Альтернатива без профайлера — лог в конце ветки анимации:
`console.log('layer children:', this.objectsLayer.children.length)` — до фикса
число только растёт по ходу раунда, после — держится в коридоре.

## 4. Вторичные подозреваемые (проверить после основного фикса)

Эти течи меньше (не 1 МБ/с), но в долгой сессии тоже копят:

- **`GameLogger`** — `_rounds.push(round)` (`src/dev/GameLogger.ts:152`) копит запись
  на каждый раунд **навсегда**, плюс вешает `__DEEP_RUSH_LOG` на `window`.
  Убедись, что логгер выключен в проде или у массива есть лимит.
- **`_breakGfx` / `_breakSpine`** (золото/камень) — путь уборки есть
  (`GameRenderer.ts:4044–4047`), но проверь, что он вызывается на **каждый** исход
  брейка (в т.ч. при прерывании раунда / лаве посреди бурения).

---

## 5. Итог

- **Главное:** один `destroy` в `GameRenderer.ts:4341` убирает основную течь ~1 МБ/с.
- **Риск фикса:** минимальный — `gfx` после анимации уже невидим и не используется.
- **Регресс-чек:** убедись, что предмет не «мигает» в момент исчезновения
  (анимация доигрывает до `alpha=0` перед destroy — так и есть, destroy в ветке `t>=1`).
